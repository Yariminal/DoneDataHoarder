# DoneDataHoarder validation report — 2026-09-27

## Scope and status

This report records the first real-corpus validation of branch `codex/safe-execution-recovery`, based on fetched `origin/master` commit `c804078`. The approval and recovery milestone was implemented in this branch. The quality and scale work below is a follow-up plan, not completed functionality.

The root reviewer independently ran the current full test suite: **190 passed in 18.16 seconds** after the Gemma 4 output bounds, failure handling, model-resolution, worker, relation-parser, and keeper API fixes. JavaScript syntax and Git whitespace checks also passed. The web UI has not been visually verified. A browser security policy blocked the local `127.0.0.1:8765` visual check after the user declined permission, and the server was stopped. No browser workaround was used.

The completed approval/recovery milestone makes the default execute selection approved-or-edited only, scopes web review actions to the active session, validates edited paths, and requires a fresh pre-commit selection preview in the web API. A process-local lock serializes web review mutations, preview validation, and commits; tracked parent and nested workers prevent a second web job or commit while a cancelled worker can still run. This does not coordinate independent CLI or server processes. Filesystem operations are journaled for **manual per-session undo**; undo checks already-restored destinations and source file type/content, while duplicate execution rejects a changed keeper. `undo --last` selects the most recent session with outstanding operations and can reverse more than one execute invocation; automatic recovery on server startup is not implemented. `.github/workflows/test.yml` and `requirements-dev.txt` now install the `dev` and `web` extras so the new FastAPI tests run in the existing CI matrix.

Relation calls now forward the selected model and bound Ollama output. The Ollama client reports output-limit truncation as an error to its caller. Cross-script relation parsing accepts fenced JSON with literal control characters only for that parser and filters members to exact input filenames. These changes address request and parsing mechanics; they do not establish that a relation group is semantically sound.

The Ollama client now defaults Gemma 4 text and vision requests to a bounded 4,096 output tokens with thinking disabled, while leaving other model families' defaults unchanged. The existing `AI inference failed:` sentinel now produces a file `ERROR` instead of a normal analysis; zero confidence stays zero. CLI `analyze --retry-errors` opts into retrying those prior AI inference errors. Structured failure categories, per-result model and extractor provenance, and a web retry control remain planned.

The validation harness and its isolation procedure are described in [validation.md](validation.md). The private independent verification artifact confirms that all six original ZIP hashes still match preparation, all **1,337 extracted files** match their original relative paths, sizes, and SHA-256 values after undo, and all **1,321 indexed database records** have their original paths and filenames. The six selective cycles committed and undid **30 operations** in total. The artifact's `all_passed` result covers files, database records, and ZIP hashes; directory topology is reported separately below. This public report uses corpus labels and representative filenames; the unredacted historical report and original evidence remain only in the local `D:\Test` validation workspace.

## Findings and next agent tasks

### P0 — Duplicate proposals confuse template similarity with disposable copies

Root visually verified that a presentation screen showing bees, one showing weather, and a blank phone mockup have distinct content, yet appear in the same 13-member perceptual-hash group at reported similarity 0.95. In Medium, numbered architectural walkthrough frames `00028.jpg` and `00040.jpg` under a walkthrough-frame folder also scored 0.95 despite visibly different camera positions; the Medium index has 36 perceptual-hash groups covering 443 candidates among 525 indexed files. The code joins all hashes connected by threshold-distance hops into one component, then stores the constant `0.95` for every member (`core/dedup.py:311–312, 373–395`). That value is neither a measured distance to the keeper nor a calibrated probability; transitive chains can include visually distinct files. Shared layout or animation sequence must not imply that one file can be trashed. Evidence: Small and Medium duplicate records, inspected originals, and the perceptual-group implementation.

A separate keeper-selection lifecycle remains incomplete: choosing a different valid group keeper leaves older duplicate proposals pointing at the former keeper. Execution now rejects them as stale, but regeneration skips existing proposals rather than refreshing them, so the user has no clear re-review path. The API now rejects generic duplicate-proposal edits and requires a keeper to belong to the selected group and session; proposal refresh after a valid change remains planned.

Hebrew review adds a dependency concern beyond visual similarity. Of 704 pending proposals, 315 moves and 93 duplicate marks target `.SHX` font resources; the font content was skipped by analysis. Moves **376–377** would place two differently named `.SHX` font files into a newly named font folder at confidence 0.80 based on their names. Some duplicate marks cite exact byte equality between differently named fonts, but a CAD drawing may refer to a specific filename and location. Large provides a concrete link: line 4 of a machine OBJ model references its adjacent material file by basename (`mtllib …`), and that file exists beside it. Pending proposal **197** would rename the material to a new material filename at confidence 0.95 without updating the OBJ reference; **260–261** would move and rename the pair into a new model folder. Pending duplicate proposal **26** would trash the washing-machine OBJ in favor of an unrelated product FBX model based on semantic similarity 0.65, despite their conflicting project identities; their 3D geometry was not inspected. None of these proposals was executed. Evidence: Hebrew and Large `reports/review.json`, the Large OBJ's `mtllib` line, and the existing MTL file. Exact bytes or semantic similarity alone do not prove that removing one path is safe for a dependent project.

**Next task:** Separate byte-identical copies from visually similar variants in both the data model and review language. Retain each candidate's actual hash distance to its proposed keeper, distinct from a calibrated decision confidence. Do not treat transitive component membership as evidence that a file is a disposable copy. Gate bulk approval of trash proposals by the evidence class, show the keeper and comparison evidence for near matches, and refresh affected proposals for re-review after a valid keeper change. Detect known dependency references and protect path-dependent resource bundles unless every reference can be updated atomically and validated in the consuming application.

**Acceptance:** A hand-labeled set retains all three distinct screens and distinct Medium frames, identifies genuine export copies, and reports precision and false-positive examples by duplicate class. Review displays measured keeper-specific distance rather than a constant 0.95; bulk trash approval excludes similarity-only candidates without separate evidence. A keeper change invalidates and refreshes affected proposals for new review. Potentially referenced `.SHX` fonts and the observed OBJ → MTL pair retain their paths by default; if references are actually rewritten, the rewrite is atomic and validated in the consuming application. Baseline-missing Large references are excluded from regression claims.

### P1 — Document extraction can turn ZIP bytes into confident content

Both PPTX files were processed through the document extractor's Latin-1 fallback. The resulting 3,000-character strings began with `PK` and contained 1,476 and 1,718 nonprintable characters, yet were marked `content_available=true` at confidence 0.9. Five STL files were skipped without a recorded reason. `ai_model` currently stores `OllamaClient`, rather than the model identifier that produced the output. This prevents a reviewer from distinguishing meaningful analysis from binary noise or tracing a proposal to its source.

**Next task:** Add format-aware PPTX text extraction and a binary/readability gate. Record a structured `unsupported`, `unreadable`, or `missing_dependency` result when content is unavailable. Save the actual model identifier/digest, prompt version, extractor name/version, and evidence source; keep calibrated operational risk separate from the model's self-reported confidence.

**Acceptance:** Valid PPTX slide text is readable and attributed; corrupt PPTX, missing extractor dependency, and binary fallback input produce explicit low-evidence outcomes with no confident filename guess. Each skipped STL has a reason. A proposal can be traced to the model, prompt, extractor, and input evidence used.

### P1 — Long runs need durable orchestration and bounded failures

Individual background jobs can reconnect after a browser refresh, but the unattended sequence is held in browser memory. A refresh or server restart can leave the current job and remaining steps out of sync. The current process tracks parent and nested workers so a cancellation cannot immediately start a competing web job; this state is not durable across restarts or shared with separate processes. The known AI inference-failure sentinel now yields `ERROR`, but structured failure categories and web retry are absent. A requested `--limit` still needs enforcement before parallel task submission.

**Next task:** Persist the run plan, step index, and checkpoints on the server; make job status and cancellation reflect worker termination. Preserve structured provider error type and retry state through analysis and proposals, expose web retry, and bound submitted work to the requested limit.

**Acceptance:** Reload and restart tests resume or clearly stop the queued run without duplicating completed work. Cancellation remains safe across processes and restarts as well as within one web process. A forced provider error retains its category and retry action in CLI and web, and cannot produce an apparently normal-confidence proposal. A limit of N submits at most N analysis items.

### P2 — Scale and review evidence need tighter feedback

All six corpora completed their planned validation workflows and selective execute/undo cycles; Medium intentionally analyzed only 48 of 525 indexed files. Analyzer work is submitted in batches of at most 50; scanner memory and representative peak usage still need measurement. A pre-commit selection preview is now present, but visual usability and per-file failure presentation are unverified. When a rename and move both affect one file, the preview shows the stored move destination while execution cascades the renamed basename, so the displayed path may differ from the final path.

**Next task:** Stream scanner records, verify and tune the in-flight analysis cap, and benchmark representative media mixes from the isolated corpora. Simulate ordered rename/move outcomes in the pre-commit preview and surface concrete dry-run failures beside affected proposals. Journal directories created by moves and remove only those that are empty during undo.

**Acceptance:** Larger runs complete within measured memory bounds without unbounded queued futures; benchmarks report files, bytes, media mix, elapsed time, memory peak, and failure count. The preview's final paths match dry-run and commit for a selected rename-plus-move pair, and a reviewer can identify every failed operation before commit. Undo leaves no newly created empty directory and never removes a nonempty or pre-existing directory.
