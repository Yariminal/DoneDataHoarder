# Iteration 3 acceptance plan

This cycle addresses the quality gaps observed in [Iteration 2](ITERATION_2_VALIDATION_REPORT.md). Run all checks on disposable, isolated collections. Original ZIPs and private corpus evidence stay outside the repository. A `content_verified` analysis means the model saw readable content; it does not certify every interpretation or make a proposal safe.

No precision, recall, useful-name rate, or end-to-end safety claim is accepted without its measured denominator and review evidence.

## Measured combined-run status (2026-09-28)

The six-ZIP disposable run extracted and physically hashed 1,337 files / 4,431,413,374 bytes; 1,321 were indexed and 16 excluded by the original policy. Nine of those exclusions were legitimate user files totaling 412,662,017 bytes. A **separate isolated inventory proof** using recovery source indexed all nine, reaching 1,330 files with only seven OS metadata exclusions, while leaving the original 1,321 database rows unchanged. The original full analysis at `158a0f1` stopped with six explicit provider-response errors and did not run downstream proposal stages. A one-shot, source- and database-guarded continuation at `9c2861a` retained the original 1,321-row denominator and retried those six plus one reviewed skipped design file. All seven became fresh, content-verified vision analyses. Final persisted coverage was 781 fresh (722 content-verified, 50 context-only, 9 metadata-only), 540 unsupported-type skips, zero errors, and zero unprocessed rows. Both relation and organization stages logged zero warnings. The original failure and pre-retry database snapshot remain available as evidence.

Root independently verified six source ZIP hashes, all 1,337 extracted file paths and bytes, 59 directories, 1,321 indexed IDs and database paths, and clean SQLite integrity. One individually reviewed rename passed targeted dry run, commit, undo, and restored-state audit. No move or deletion was applied. This satisfies a narrow real filesystem cycle on the disposable collection; it does not prove that the seven rejected move proposals or 65 non-exact comparisons are safe to apply.

The 65 non-exact proposals received a blind stratified keeper-relative sample of 16 labels: 10 distinct, 5 derivative or role variants, 1 uncertain, and no established interchangeable copy. This sample is not a population precision estimate and provides no recall denominator. Original Office XML supported the broad subject in four of five combined rename suggestions; one was misleading. Only one was selected for the rename/undo proof; three were deferred over usefulness or date caveats. Matching metadata dates were not treated as verified event dates. All seven move suggestions would split reviewer-identified named collections and were rejected. Preserved projects and restored original folders are safety outcomes, not newly organized files.

The next source revision adds bounded deterministic drawing metadata, guarded backup routing, named-folder move suppression, and fresh keeper/candidate evidence with stale-review rejection for non-exact approval. Focused proof routed three real drawing files to `metadata_only` without model calls. On a copied database, the organizer removed all seven unsafe moves (893 to 886 total proposals) without changing non-move proposals or the source/live databases. These fixes are separate from the measured `9c2861a` run; a full corpus rerun is still needed to measure their combined effect. Desktop and narrow-screen browser acceptance remains pending, as do real consuming-app dependency checks and 100–500 GB physical capacity measurements. The 4.43 GB combined run and earlier 100,000-row logical fixtures cannot establish the latter.

At `9c2861a`, the full suite passed 351 tests and all 10 CI checks passed. The later worktree revision passed 372 Python tests, with one Windows symlink-creation test skipped for OS permissions; the always-on reparse guard, JavaScript syntax, and all three standalone Node UI checks passed. Its CI result remains pending. The 17 skipped backups in the original continuation have same-stem companions but different hashes, so their skipped status must not be read as duplicate or disposable. The separate 1,330-row inventory proof preserves them even before any content-analysis improvement.

The synthetic naming examples in `tests/test_quality_iteration3.py` are regression controls authored with this implementation, not an independent holdout. The quality gate also requires unseen hand-reviewed examples with labels and denominators before a naming rate is reported. Project preservation includes the selected root itself when it contains an explicit project manifest. The organization coverage endpoint distinguishes preserved, proposed, existing-folder-retained (structural heuristic only), and needs-review files; "fully organized" requires explaining every remaining needs-review file rather than equating zero operations with success.
